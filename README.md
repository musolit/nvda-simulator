# NVDA 매도 시뮬레이터

개인용 NVIDIA(NVDA) 보유 주식 매도 시뮬레이터. Next.js + TypeScript + Tailwind CSS
기반이며, Vercel에 그대로 배포할 수 있습니다.

**로그인, 회원가입, 외부 데이터베이스가 전혀 없습니다.** 모든 데이터는 접속한
브라우저의 localStorage에만 저장됩니다. 즉:

- Google/이메일 로그인 없음
- 서버에 저장되는 사용자 데이터 없음 (Supabase 등 백엔드 서비스 불필요)
- 사이트에 접속하면 바로 앱을 사용할 수 있음
- 새로고침하거나 브라우저를 껐다 켜도 데이터가 유지됨 (같은 브라우저 기준)
- 다른 기기/브라우저와는 자동 동기화되지 않음 (필요하면 설정의 JSON 백업으로
  내려받아 다른 기기에서 복구)

## 기능

- 대시보드: 계좌 기준 보유수량/평균매입가, 현재가·환율 입력 → 실시간 평가금액/손익/수익률
- 시뮬레이터: 매도수량 시뮬레이션(FIFO 취득원가/실현이익/세금/세후 확보금액), 목표현금 역산, 100/200/300/500/1000주 빠른 비교
- 거래내역: 실제 매수/매도 기록 CRUD, 키움 카카오톡 체결알림 텍스트 가져오기(파싱→미리보기→확인→저장)
- 설정: 세금/공제/계좌 기준값 설정, JSON 백업 다운로드/복구, CSV 내보내기, 전체 데이터 초기화

## 사용 시작하기

별도의 외부 서비스 설정이 전혀 필요 없습니다.

1. 이 저장소를 Vercel에 배포합니다 (환경변수 설정 불필요).
2. 배포된 사이트에 접속합니다.
3. 최초 접속 시 "초기 데이터 가져오기" 화면이 나타납니다. 보유수량, 평균매입가,
   매수 lot(확정 내역 + 미확인 조정분 등)을 담은 JSON을 붙여넣거나 파일로
   업로드하세요. 화면에서 "예시 템플릿 다운로드"를 누르면 정확한 JSON 형식을
   확인할 수 있습니다(예시 안의 숫자는 전부 가상의 값입니다). 데이터를 아직
   준비하지 못했다면 "나중에 하기"를 눌러 빈 상태로 시작한 뒤, 거래내역 화면에서
   매수 lot을 하나씩 직접 추가해도 됩니다.

### 로컬 개발

```
npm install
npm run dev
```

http://localhost:3000 접속.

## 데이터가 저장되는 곳과 백업

모든 데이터(매수 lot, 매도 기록, 계좌 기준값, 세금 설정, 현재가/환율 입력값)는
`window.localStorage`에만 저장됩니다. 서버로 전송되지 않습니다. 따라서:

- 브라우저 데이터를 지우거나 시크릿 모드를 벗어나면 데이터가 사라질 수 있습니다.
- 다른 기기나 다른 브라우저에서는 데이터가 보이지 않습니다.

**설정 화면의 "JSON 백업 다운로드"를 주기적으로 사용해 데이터를 보관하세요.**
같은 파일을 "JSON 백업 파일로 복구"에 다시 업로드하면 복원됩니다(이미 있는
항목과 id가 겹치면 건너뜁니다). CSV 내보내기는 표 형태로 확인/보관하는 용도이며
복구에는 사용되지 않습니다. 설정 화면의 "위험 구역"에서 전체 데이터를 초기화할
수 있으며, 실수 방지를 위해 확인 문구 입력이 필요합니다.

## 데이터 구조 및 계산 기준

- 계좌 기준값(보유수량 · 평균매입가)은 설정 화면에서 직접 입력/수정하며, 항상
  이 값이 대시보드의 최우선 표시 기준입니다.
- 매수 lot은 "확정"(실제 체결이 확인된 lot)과 "미확인 조정분"(실제 체결 내역을
  확인할 수 없어 수량 차이를 보정하는 lot, 평균단가만 역산되어 있고 개별 체결로
  표시되지 않음)으로 구분됩니다. 조정분은 FIFO 정렬상 항상 마지막에 위치하므로,
  확정 lot 합계 이하를 매도하는 일반적인 시뮬레이션에는 영향을 주지 않습니다.
- 세금 계산은 실제 세무신고가 아닌 의사결정용 "예상치"입니다. 매수 시점의 세법상
  원화 환율 기록이 없어 사용자가 입력한 현재 환율을 일괄 적용하는 간편 추정 방식을
  사용합니다.
- 시뮬레이션(매도 시뮬레이터, 목표현금 역산, 빠른 비교)은 계산 결과만 보여줄 뿐
  실제 저장된 보유수량이나 거래내역을 절대 변경하지 않습니다. 실제 매매를
  반영하려면 거래내역 화면에서 별도로 기록해야 합니다.

## 개발

```
npm run typecheck   # 타입 체크
npm run lint        # ESLint
npm test            # vitest (핵심 계산 로직 단위 테스트)
npm run build        # 프로덕션 빌드
```

핵심 계산 로직(FIFO, 세금, 목표현금 역산, 카카오 파서)과 localStorage 저장/불러오기
로직은 `src/lib`에 UI와 분리되어 있고, `src/lib/**/__tests__`에 테스트가 있습니다.
테스트는 합성(fixture) 데이터만 사용하며 실제 거래내역은 저장소 어디에도
포함되어 있지 않습니다.
